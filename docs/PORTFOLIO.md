# 차곡

후불 거래의 청구와 입금을 관리하는 미수금 확인 서비스입니다. 이름이나 금액이 비슷하다는 이유로 자동 연결하지 않고, 사용자가 근거와 현재 잔액을 확인한 뒤 연결하도록 만들었습니다.

## 사용 흐름

청구·입금 등록 → 연결 후보 조회 → 연결 금액 검토 → 확정 → 미수 확인 → 취소

청구 100,000원에 입금 40,000원을 연결하면 미수는 60,000원이 됩니다. 나머지 60,000원을 연결하면 0원이 되고, 두 번째 연결을 취소하면 60,000원으로 복구됩니다.

## 핵심 설계

### 동시 요청의 초과 배분 방지

`AllocationService.confirm/cancel`은 입금과 청구를 같은 순서로 잠근 뒤 현재 잔액을 검사합니다. 요청 금액이 가용액을 넘으면 전체 요청을 롤백합니다.

### 재전송의 중복 처리 방지

요청 키와 정규화한 내용의 해시를 결과와 함께 저장합니다. 같은 요청은 기존 결과를 반환하고, 같은 키로 다른 내용을 보내면 충돌로 처리합니다. 모바일에서도 응답을 받지 못한 요청의 키를 유지합니다.

### 확정·취소 이력 보존

취소 시 청구·입금 원본과 배분 행을 삭제하지 않습니다. 취소 사실과 사유를 추가하고 활성 배분을 기준으로 잔액을 계산합니다. 과거 명령 응답과 현재 상태는 별도로 조회합니다.

### 성공한 후보 실행만 사용량 반영

후보 결과와 사용량을 같은 트랜잭션으로 저장합니다. 월별 사용량 행을 잠가 동시 요청에서도 한도를 지키며, 실패와 동일 요청 재전송은 추가 차감하지 않습니다.

## 개발 방식

AI 에이전트를 분석·구현·독립 검토 역할로 나누어 활용했습니다. 실제 DB와 브라우저에서 재전송·잔액·화면 전환을 확인하며 수정했습니다. 서비스의 금액 계산과 거래 확정은 Java/DB가 담당합니다.
