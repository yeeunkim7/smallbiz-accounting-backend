## 2. 업무 범위와 지켜야 할 기준

청구 등록 → 은행 입금 등록 → 규칙 후보 → 사용자 검토·확정 → 미수금 조회 → 필요 시 취소를 FREE 핵심 흐름으로 유지한다. 입금 등록·후보 조회만으로 채권을 소멸시키지 않는다.

- 기존 `business_event`의 CHARGE_EXPECTED/SETTLEMENT_EXPECTED/REFUND_EXPECTED는 예정 현금흐름이며 신규 청구가 아니다. `daily_review.REVIEWED`는 개별 입금 확정이 아니다. 기존 전역 자료를 계정에 자동 연결하지 않는다.
- 원화 정수 금액, tenant 소유 거래처·청구일·지급기한·입금과 다대다 배분을 사용한다. 부분 입금, 한 청구에 여러 입금 연결, 한 입금의 여러 청구 분할을 지원한다.
- 미배분 입금·미수·기한 초과 잔액은 분리한다. 자료 없음·합계 일치·개별 매칭도 구분하며 조회 결과가 없다는 이유로 미입금·미업로드라 단정하지 않는다.
- 금액 계산과 확정은 Java·DB 트랜잭션으로 수행한다. 취소는 사유·감사를 남기며 원본·배분 이력을 지우지 않는다.
- FREE/STANDARD는 키 존재 여부와 무관하게 서버에서 모델 호출을 차단한다. PRO 자산은 조회 전용·최대 5회 모델 요청 제한을 유지하며 자동 확정·거래 변경은 제공하지 않는다.
- 자동 알림, 세금계산서, 은행 인증 연결, 송금, 다통화, 실제 결제/구독은 현재 FREE 범위 밖이다. 완전한 상업 회계 원장을 구현했다고 주장하지 않는다.

## 3. 정책 가설과 실제 제한

FREE 0원·월 10회, STANDARD 월 9,900원, PRO 월 약 30,000원은 초기 가설이다. 가격을 비즈니스 로직에 하드코딩하지 않는다. 현재 FREE 기본 횟수는 서버 설정이며 STANDARD/PRO 기본 한도 0은 별도 정책 설정 전 차단을 뜻한다.

정상 SUCCESS 결과가 저장될 때 1회이며 자료가 없는 정상 결과도 포함한다. 실패·동일 요청 재생, import·조회·배분·취소는 추가 차감하지 않는다. 성공 결과·event·counter가 같은 동기식 트랜잭션에서 commit/rollback된다. 월 경계·재요청·동시성 계약은 [사용량 문서](RECEIVABLES_USAGE.md)를 기준으로 한다. 이전 lease/fencing 제안을 대체한 이유와 판단 주체는 [ADR 0002](adr/0002-receivables-decisions.md)에 있다.

CSV 기본 한도는 1MiB/1,000행, 설정 안전 상한은 5MiB/10,000행이다. 스트림 제한·검증·전체 롤백과 원본 증거 보존은 [CSV 계약](RECEIVABLES_IMPORT.md)에 정의한다. 계정 저장량·요청 속도·보존/삭제 등 운영 제한은 후속이다.

## 4. 다음 작업과 결정 절차

1. 개발자가 [의사결정 기록](adr/0002-receivables-decisions.md)의 핵심 코드·트레이드오프를 확인한다. 과거 AI 구현을 사용자 승인으로 소급하지 않는다.
2. 모바일 CSV 화면 등 다음 기능 하나의 흐름·오류 처리·검증 범위를 정한다. API는 재사용하고 주요 모델·업무 규칙 변경이 필요하면 구현 전에 사용자 결정을 받는다.
3. iPhone/Android 실기기와 Windows 개발 절차, 접근성·SecureStore·키보드·탐색을 검증한다. 브라우저 확인으로 대신하지 않는다.
4. 제한 파일럿 전 개인정보·권한·요청 제한·보존/삭제·계정 보호와 실제 사용자의 최초 업무 흐름을 확인한다.
5. 앱인토스 적용은 자격·SDK·정책을 먼저 검토한다. Expo/Java API를 보존하며 출시·유료 서비스·스토어·구독은 별도 승인 후 진행한다.

일반 구현은 기능 단위로 진행하고 독립 검토 후 핵심 코드·실행 결과를 보고한다. 중요한 선택과 최종 사용자 검토 절차는 [AGENTS.md](../AGENTS.md)를 따른다.

## 5. 검증 기준과 기존 근거

부분/묶음/분할 입금, 과배분·음수·0·overflow 거부, 기한 경계, 취소 복원, 동일 키·다른 내용 충돌, 마지막 한도 경쟁·월 변경·실패 rollback, tenant 격리와 FREE 모델 0호출을 유지한다. 기존 회귀는 `reconciliation_test`와 합성 자료만 사용한다. 개발 원본 행 수 비교는 바이트 동일성 검증과 구분한다.

## 첫 기능 단위 진행: 인증·사업체·AI 경계

P0 이후 계정·사업체·세션을 위한 V8과 서버 권한 경계를 구현했다. 기존 전역 금융 API는 기본 거부하며, legacy-dev 프로파일과 명시적 옵션을 함께 사용한 익명 개발 fixture만 보존한다. FREE/STANDARD와 미인증 사용자는 모델을 호출할 수 없고, PRO도 tenant 전용 도구 완성 전까지 차단한다.

[구현 API·실행 안내](AUTH_FOUNDATION.md) · [독립 검토](auth-security-review.md). 전체 104개 테스트가 통과했다. 다음 기능 단위는 tenant 소유 거래처·청구·입금 직접 등록이다. 배분·미수 계산·quota·Expo와 운영 계정 보호 작업은 남아 있다. 이 기록은 앞선 P0 당시 기능 소스 미변경 기록과 구분한다.

## 등록 단계 완료

사업체별 거래처·청구·입금 직접 등록 및 목록/상세 API와 V9를 추가했다. 전체118개 테스트 성공, 금액·날짜·테넌트 격리·동시 idempotency 검증을 포함한다. 아직 배분·미수/연체·사용량은 계산하지 않는다. 다음 기능 단위는 수동 배분 확정·취소와 정확한 미수/연체 계산이다.

## 수동 배분·미수 계산 단계 완료

부분·묶음 입금의 수동 확정, 사유 있는 취소, 원본 보존·감사 이력과 현재 미수/연체/미할당액 조회를 구현했다. 전체 135개 테스트가 통과했다. [배분 계약](RECEIVABLES_ALLOCATION.md). 자동 후보, CSV 수금 가져오기, 월 성공 실행 사용량, Expo와 공개 운영 준비는 남아 있다.

## 규칙 후보 생성 단계 완료

청구·입금의 현재 가용액과 이름·날짜 근거로 규칙 후보를 생성하고 불변 실행 결과를 저장한다. 자동 배분하지 않으며 후보 0건을 입금 누락으로 확정하지 않는다. 전체149개 테스트 통과, V11 및 [API 계약](RECEIVABLES_MATCHING.md)을 추가했다. 월별 성공 실행 quota는 아직 적용 전이므로 공개 FREE 서비스가 준비됐다고 표시하지 않는다. 다음 기능 단위는 tenant 소유 은행 CSV 가져오기와 원본 추적이며, 이후 저장된 matching run의 성공 사용량을 서버에서 제한한다.

## Tenant 은행 CSV 가져오기 구현 — feature 3b

V12와 사업체별 가져오기·목록·상세·페이지 원본 조회 및 입금 원본 역추적 API를 추가했다. 표준 6열 CSV에 사업체 내 은행 계좌 별칭과 명시적인 안정 거래 ID를 요구한다. 동액·동일 날짜의 별도 거래를 보존하고 겹치는 파일은 거래 ID로만 중복을 방지한다. 원본 셀과 파일 해시, 출금 포함 행별 증거를 보존하며 수입 입금만 `BANK_CSV`로 등록한다. 은행 계좌 소유를 인증하거나 청구를 자동 연결하지 않는다. 기본 1MiB/1000행, 설정 상한 5MiB/10000행, UTF-8 엄격 검증, 사업체별 idempotency·파일/거래 중복 처리와 전체 롤백을 적용했다. [CSV/API 계약](RECEIVABLES_IMPORT.md). 검증 최종 결과는 작업 기록에 추가한다. 다음 기능 단위는 저장된 matching run의 성공 사용량을 서버에서 제한하는 작업이며, 모바일·공개 운영 준비는 남아 있다.

## 기능 3c — 월별 성공 실행 사용량

V13과 [사용량 API](RECEIVABLES_USAGE.md)를 추가했다. 성공 결과·승인 월·고유 usage event·counter를 기존 bounded 동기식 트랜잭션에 결합하며 FREE 기본10은 서버 설정 가설, STANDARD/PRO 기본0은 명시적 설정 전 fail-closed다. 같은 키/과거 결과 재생은 추가 차감하지 않고 실패·quota 거부는 키까지 rollback한다. 현재 월 조회와 429/reset 정보를 제공하며 모바일·공개 운영 준비는 남아 있다. 검증 최종 결과는 작업 기록에 별도 기록한다. 다음 기능 단위는 기존 API를 재사용하는 Expo 핵심 화면이다.

## 기능 4a — Expo 모바일 코어
