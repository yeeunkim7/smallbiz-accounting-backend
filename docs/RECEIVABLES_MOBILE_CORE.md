# Expo 모바일 코어 (기능 4a)

이 문서는 2026-11-01 기능 4a의 설계·검증 이력이다. 당시의 세 탭 및 후보 검토 후속 설명은 이후 기능 4b에서 변경됐다. 현재 네 탭과 입금 연결 검토·확정·취소는 [모바일 입금 연결](RECEIVABLES_MOBILE_MATCHING.md), 전체 구현 상태는 [개발 계획](RECEIVABLES_FREE_MVP_PLAN.md)을 따른다. 아래 8개 테스트 결과는 당시 실행 기록으로 보존한다.

## 구현 전 흐름·구조 결정

로그인/가입에서 실제 계정 또는 별도 `샘플 체험`으로 진입한다. 실제 계정의 여러 사업장은 서버 소속 목록에서 선택한다. 홈은 오늘(서울)의 서버 전체 미수·연체·미연결 입금 합계와 원본 건수로 자료 유무를 구분한다. 청구 추가/입금 추가로 바로 입력하며, 장부는 청구·입금·거래처를 페이지 단위로 조회한다. 청구를 누르면 서버 현재 배분액·잔액 상세를 연다. 계정은 서버 플랜·월 사용량과 로그아웃을 제공한다.

다섯 업무 표면은 홈, 등록, 장부, 청구 상세, 계정이다. 후보 검토와 CSV는 다음 기능이며 작동하는 것처럼 보이는 버튼을 만들지 않는다. 샘플은 읽기 전용 합성 상수이며 네트워크·사용량·실자료 복사가 없다.

하단 3개 탭(홈/장부/계정), 상단 사업장 문맥, 960px 최대 콘텐츠, 모바일 단일 열, 넉넉한 여백과 절제된 청록색을 사용한다. 금액은 십진 문자열/BigInt로만 포맷하고 서버 합계를 다시 계산하지 않는다. 날짜는 date-only를 보존한다. native는 SecureStore, web은 메모리에만 토큰을 보관한다. 금융 POST는 변경 없는 입력에 동일 키를 유지하고 불확실한 실패를 자동 재시도하지 않는다. 세션 세대와 화면 요청 취소로 계정 전환 뒤 늦은 응답을 폐기한다.

## 검증·실행

구현 전 계획을 아래 실제 검증 기록으로 갱신했다. 웹 렌더와 실제 API 흐름은 통과했으며 native 실기기·스토어 빌드는 미검증이다.

## 구현 결과와 경계

`mobile/`에 Expo SDK 58.0.22 / React Native 0.88.1 / React 19.3.0 / TypeScript 6.0.3 기반 앱을 구성했다. 2026-11-01 npm의 공식 `expo-template-blank-typescript@58.0.31` 패키지를 확인하고 사용했다. 의존성은 Expo bundledNativeModules와 lockfile로 고정한다. 아이콘은 저장소에서 작성한 단순 막대 모양 원본 자산이다. 배포용 앱 식별자·서명·EAS·스토어 설정은 추가하지 않았다.

- `App.tsx`: 안전 영역/키보드 회피, 로그인 진입, 복수 사업장 선택, 하단 탐색, Android 뒤로, 사업장 단위 초안 수명.
- `src/api.ts`, `session.ts`, `vault.ts`: 검증된 API origin, 타임아웃, 안전한 오류, 현재 세션 401 잠금, 지연 응답 세대 검사, 순서 보장 SecureStore 쓰기. Web은 토큰 영속 저장을 하지 않는다.
- `src/forms.tsx`, `commands.ts`: 직접 등록·실제 날짜/정밀 금액 검증, canonical payload 키 재사용, 성공 후 새 키, 수동 재시도, 전송 중 탐색/입력 잠금, 오류 후 초안 유지.
- `src/screens.tsx`, `data.ts`: 홈 서버 summary, 페이지마다 최대 10건 목록 및 보이는 항목의 잔액 조회, 서버 청구 잔액 상세, 서버 사용량. `asOf`는 연체 비교 기준이며 전체 현재 장부를 과거 스냅샷으로 표시하지 않는다. 서버가 제공하지 않는 연체 건수나 후보 건수를 만들지 않는다.
- `src/sample.ts`: 고정 기준일과 합성 서버 응답 모양의 읽기 전용 체험. 실제 네트워크, 사용량, 데이터 복사 없음.

로그아웃·사업장 변경·재실행은 초안을 버린다. 등록 중 뒤로/탭 탐색을 막아 같은 폼을 다시 열어 동시 전송하거나 늦은 성공이 새 초안을 지우는 상황을 방지한다. 등록 성공 안내와 이후 목록 조회 오류는 구분한다. Native 안전 저장 실패 시 로그인 성공으로 진입하지 않고 새 서버 세션 폐기를 시도한다. Web의 새로고침 로그아웃은 의도한 제한이다.

이 단계는 후보 검토/할당 내역·확정·취소, CSV 가져오기, 복구/이메일 인증, 개인 정보·도움말 외부 문서, 공개 운영 정책을 포함하지 않는다. 실행할 수 없는 버튼이나 가짜 링크를 두지 않는다. 같은 서버 플랜을 조회해 표시하지만 로컬 plan으로 권한을 부여하지 않는다. 한도/잔액/AI 판단을 클라이언트에서 계산하지 않는다.

## 실행과 검증 상태

[mobile/README.md](../mobile/README.md)의 설치·API 주소·Windows/기기 안내와 [실제 브라우저 검증 기록](RECEIVABLES_MOBILE_VALIDATION.md)을 따른다. Native SecureStore/키보드/접근성·글자 확대·실기기와 공개 스토어 검증은 미실행 상태다. 브라우저 검증은 루트 작업의 실제 결과를 별도 기록하며 이 문서는 실행하지 않은 항목을 완료로 간주하지 않는다.

최종 로컬 정적 검증: 핵심 Node 테스트 8개 성공, `npm run typecheck` 성공, `expo export --platform web` 성공. 제한된 네트워크에서는 Expo의 온라인 React Native Directory 조회가 거절되어, 설치된 SDK의 bundledNativeModules를 사용한 오프라인 의존성 확인을 수행했고 up-to-date였다. 이 확인은 실기기나 온라인 Expo Doctor 전체 검증을 대신하지 않는다.

320px의 큰 금액 검토에 따라 홈/상세의 대표 금액은 금액 계산 없이 **서식화된 문자열과 실제 영역 너비만**으로 글자 크기를 조절한다. 매우 긴 합계나 글자 확대에서는 금액을 자르거나 숫자 중간을 줄바꿈하지 않고 가로로 읽을 수 있게 하며 안내를 표시한다. `UNPAID`는 은행에 입금이 없다는 추정을 피하기 위해 `입금 미연결`로 표시한다.
