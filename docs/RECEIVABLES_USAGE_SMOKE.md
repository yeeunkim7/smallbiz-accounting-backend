# 월별 성공 대사 이용량 실행·검증

## 로컬 확인

개발·테스트 DB를 분리하는 기존 `backend-java/README.md` 설정을 유지한다. 금액 계산과 거래 확정은 기존 Java/DB 경로를 사용하며 이용량 기능은 AI를 호출하지 않는다.

`backend-java`에서:

```sh
bash gradlew build
bash gradlew bootRun
```

로그인한 사업체로 `GET /api/v1/tenants/{tenantId}/matching-usage`를 호출하면 서버가 판단한 한국 시간 기준 월, 등급, 정책 버전, 한도·완료·남은 횟수와 다음 초기화 시각을 확인할 수 있다. 토큰은 호출 도구의 비밀 변수로 관리하고 출력하지 않는다. 월은 클라이언트가 지정하지 않는다.

기본 FREE 한도는 월10회라는 제품 가설이다. 서버 설정 `app.receivables.usage.free-limit`으로 변경하며 실제 가격·결제와 연결하지 않는다. 로컬 검증에서만 이 값을2로 낮추면 다음 흐름을 빠르게 확인할 수 있다.

1. 서로 다른 `Idempotency-Key`로 후보 생성에2회 성공한다.
2. 세 번째 신규 실행은429 `MATCHING_MONTHLY_LIMIT`이며 `Retry-After`와 사용량·초기화 시각을 반환한다.
3. 이전에 완료한 키/본문을 재전송하면 기존 결과를 반환하고 추가 차감하지 않는다.
4. 소진 뒤에도 결과 조회·CSV 등록·수동 배분·취소는 가능하며 횟수를 늘리지 않는다.

자료가 없어도 후보 실행이 정상 완료돼 결과가 저장되면1회다. `NO_ELIGIBLE_SOURCES`는 입금 누락이나 파일 미업로드의 증명이 아니다. 모바일에서는 실행 전 안내와 서버 응답을 함께 보여줄 예정이다.

## 검증 결과

2026-11-01 Java21.0.12.1/PostgreSQL17, 개발·테스트 DB 분리 상태에서 확인했다. 시작 시 중지돼 있던 PostgreSQL을 복원했고 V12 기준을 확인한 뒤 V13을 적용했다. 개발 원본 `vendor/business_event/bank_transaction/upload_file` 건수는 전후 `1/1/1/2`로 같았다. 이는 건수 비교이며 원본 행 전체 내용의 해시 검증은 아니다.

관리형 클라우드의 `backend-java`에서 실행한 최종 명령:

```sh
source /workspace/.local/env.sh
bash gradlew --offline --no-daemon \
  --project-cache-dir /workspace/.local/gradle-project build --rerun-tasks
```

전체180개(기존165+신규15), 실패·오류·스킵0, XML21개다. `BUILD SUCCESSFUL in 52s`와 JAR 생성을 확인했다. 개발 DB 거부 초기화와 Gradle의 실제 AI 키 차단을 유지했다. 새 통합 테스트는 마지막1회 동시 경합·첫 월 행 동시 생성·중복/상이 키·월 경계·기존 결과 소급 차감 방지·검증/원본 정합성/저장 오류 전체 롤백·현재 등급 변경·권한 철회·한도 후 CSV/배분/취소·DB 제약을 검증한다. 테스트의 `UsageClock`은 사용량 시계만 대체하며 인증 시계는 바꾸지 않는다.

빌드한 JAR를 `reconciliation_test`에 연결하고 로컬 검증용 한도만2로 설정해 다음11개 HTTP 시나리오를 통과했다.

1. 상태 조회200, 미인증 사용량 조회401.
2. 한국 시간 기준 현재 월·한도2·완료0·잔여2, 반복 조회 불변.
3. 잘못된 날짜 요청400, 사용량0 유지.
4. 자료 없는 정상 완료 결과가 저장되면1회 차감됨.
5. 동일 키·본문 재전송은 동일 결과, 완료1 유지.
6. 같은 키·다른 본문은409.
7. 두 번째 성공 후 세 번째 신규 실행429. 헤더·본문의 재시도 초 일치, 완료2·잔여0·미래 초기화 시각 확인.
8. 소진 후 기존 결과 조회·목록·동일 키 재전송 가능. 임의 월 query는400.
9. 소진 후 CSV에서 입금2건 등록 가능, 완료2 유지.
10. 소진 후 두 입금 배분으로 청구100,000원의 미수20,000원, 취소 후100,000원 복구. 원본 조회 가능, 완료2 유지.
11. 다른 사업체 사용량 접근403, 별도 사업체 사용량은0.

합성 자료만 사용했고 생성한 두 테스트 계정·사업체·금융 자료·이용량 행은 정리했다. 개발 서버에서는 V13 적용과 `/health`200만 확인했다. HTTP 서버의 실제 API 키를 비우고 AI 스위치를 껐다. 모델 호출이 없는 코드 경로와 테스트 mock 무호출을 확인했으며 유료 모델 검증은 수행하지 않았다.

실행 로그는 관리형 환경의 `/workspace/.local/run/usage-targeted.log`, `usage-full-build.log`, `usage-http-smoke.log`, `usage-http-app.log`, `usage-dev-app.log`다. [독립 검토](receivables-usage-review.md)에서 코드와 실행 근거를 별도로 확인했다. 이번에는 화면·브라우저·앱스토어 검증을 수행하지 않았다. 다음 단계는 Expo 모바일 핵심 흐름이다.
