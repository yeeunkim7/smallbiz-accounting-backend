# 하루 AI 검토 — 제품·화면 설계

> 문서 범위: 기존 하루 AI 검토 화면의 설계·검증 이력이다. 현재 미수금 화면은 [모바일 설계](receivables-mobile-plan.md)를 따르며 PRO AI는 보존 자산이다. 아래 fixture 화면 검증은 실제 모델 호출 검증이 아니다.

상태: 구현 전 설계. 확인일 2026-10-31 (한국 시간). 화면 검증 결과는 아래에 별도로 기록한다.

## 대상과 핵심 흐름

우선 대상은 업무 CSV와 은행 CSV를 이미 가지고 있고, 하루 입출금 차이의 이유를 찾는 소규모 조직의 정산·운영 담당자다. 시장 조사의 1차 가설이며 사용자 인터뷰로 검증된 세그먼트는 아니다. 전체 장부·세무 서비스를 대체하지 않는다.

첫 사용: 날짜 선택 → 하루 조회 → 입금·출금 자료와 차이 확인 → AI 검토 요청 → 사실/가능한 원인/추가 확인을 읽음 → 인용 원본과 업로드 정보 확인. 자료가 없으면 업로드 안내와 CSV 예제로 연결한다. 거래가 조회되지 않는 것만으로 파일 미업로드를 단정하지 않는다.

기존 일별·월별·CSV 업로드·이력·거래처 흐름은 유지한다. 새 `AI 검토` 화면을 주요 진입으로 추가하고, 기존 일별 목록의 날짜와도 연결한다. 이번 핵심 과업에는 별도 소개 페이지보다 앱 안의 짧은 가치 설명과 최초 사용 안내가 적합하다. 별도 마케팅 랜딩은 실제 유입 실험 후 결정한다.

## 정보 구조

1. 헤더: 제품명 `입출금 대사`, 주요 메뉴 `AI 검토 / 일별 / 월별 / 업로드 / 이력 / 거래처`. 모바일에서도 가로 스크롤 메뉴로 접근 가능하고 선택 상태를 밑줄·텍스트 굵기로 표시한다.
2. 작업 헤더: 작은 `하루의 차이를 근거로 확인하세요` 설명, 큰 `하루 검토`, `거래를 변경하지 않는 읽기 전용 검토` 보조 문구.
3. 날짜 도구막대: 명시적 `검토할 날짜` label, native date input, `하루 조회`. 사용자가 선택한 날짜는 페이지 주요 제목에도 표시한다.
4. 하루 요약: 입금·출금 두 영역. 각 영역은 자료 상태 → 업무/은행 건수 → 예정/실제/차이 순서. `합계 일치`와 `자료 없음`은 다른 문구·아이콘. `차이 = 실제 − 예정`을 짧게 표시한다.
5. AI 검토: 제목, 읽기 전용 badge, `AI 검토 시작` 또는 `다시 검토` 버튼. 네 구역 `확인된 사실 / 가능한 원인 / 추가 확인 / 확인한 근거`. 도구·내부 API·모델 trace 등은 사용자 화면에 노출하지 않는다.
6. 원본: 업무/은행 탭 또는 두 섹션, 방향 필터, 전체 건수와 페이지. 각 행은 날짜·유형·금액·설명, 더 보기에서 원본 ID·원본 행·관련 업로드를 확인한다. 근거 링크 클릭 시 해당 원본 영역으로 이동하고 focus를 준다.
7. 관련 업로드: 원본에 연결된 uploadId에 대해 파일명·유형·등록일·행 수 표시. 조회된 관련 파일 없음은 `이 날짜의 조회 결과에 연결된 업로드가 없습니다`로 설명한다. 전체 업로드 미존재라고 단정하지 않는다.

## 시각 규칙

- 배경 `#F5F7F8`, 표면 `#FFFFFF`, 본문 `#172B2A`, 보조 `#5D706D`, 선 `#DDE5E3`.
- 주 강조 `#086F63`, hover `#055A50`, 연한 강조 `#EAF5F1`. 강조는 실행 버튼·선택 상태·근거 링크에 집중한다.
- 일치 `#16634A`/`#EAF6EF`, 차이·확인필요 `#9A4210`/`#FFF4E8`, 오류 `#B42318`/`#FFF0EF`, 자료 없음 `#52635F`/`#EFF3F2`. 상태 텍스트와 아이콘을 항상 함께 사용한다.
- 시스템 한글 글꼴 `-apple-system, BlinkMacSystemFont, "Segoe UI", "Apple SD Gothic Neo", "Malgun Gothic", sans-serif`; 외부 폰트 다운로드에 의존하지 않는다.
- 제목 30–34px/700, 섹션 19–20px/650, 본문 15–16px/1.6, 설명 13–14px, 주요 금액 28–32px/700. 최소 본문 14px. 숫자 `font-variant-numeric: tabular-nums`.
- 간격 4/8/12/16/24/32/48px. 데스크톱 본문 최대 1180–1240px, 좌우 여백 32px, 모바일 20px. 표면 radius 14–18px, 입력·버튼 10px, 불필요한 그림자 대신 얇은 선.
- 버튼·입력 터치 높이 최소 44px. 주 버튼은 화면 과업별 하나. 키보드 focus는 3px outline + 3px offset, 그림자로만 표시하지 않는다.
- 카드에 카드를 거듭 넣지 않는다. 큰 숫자·단정한 행·넉넉한 여백으로 구조를 전달한다.

## 값과 상태 문구

- 금액은 `1,234,567원`, 표에서는 우측 정렬. 음수는 `−12,345원`, 양수 차이는 `+12,345원`, 0차이는 `0원`. 단위는 표 제목 또는 값에 일관되게 둔다. 입금·출금 차이를 상계해 하나의 숫자로 만들지 않는다.
- 날짜는 한국어 설명에 `2026년 10월 31일`, 표에서는 `2026.10.31`, 날짜 입력은 브라우저 native 형식을 사용한다.
- 자료 없음: `비교할 자료 없음` + `업무 0건 · 은행 0건`. 숫자만 0=0으로 보여주지 않는다.
- 한쪽 자료: `업무 자료만 있음` 또는 `은행 자료만 있음`; 파일 누락 추정 금지.
- 양쪽 합계 같음: `합계 일치`; 항상 주변에 `개별 거래 매칭은 평가하지 않았습니다` 설명.
- 검토 상태는 금액상태와 독립: `미검토 / 검토 완료 / 재확인 필요`. AI 의견 생성 후에도 수동 검토 상태를 자동 변경하지 않는다.
- AI 대기: `금액과 원본을 바탕으로 확인할 내용을 정리해 드려요.`
- AI 진행: `원본 근거를 확인하고 있어요` + spinner + `aria-live=polite`; 과도한 세부 도구 진행 상황은 숨긴다.
- AI 설정 불가: 사용자에게 `현재 AI 검토를 사용할 수 없습니다. 금액과 원본은 계속 확인할 수 있어요.` 표시. 키·환경변수명은 설정 문서/관리자 안내에만 둔다.
- AI 오류: 원인에 맞는 안전한 문구와 `다시 시도`; 기존 summary·원본은 유지. API 원문·스택·비밀값 표시 금지.
- AI 사실에는 인용 근거, 가능한 원인에는 `추정` label, 추가 확인에는 사람이 할 구체 행동을 붙인다.

## 상호작용과 접근성

- 날짜 변경 즉시 이전 AI 결과를 숨기거나 `이전 날짜 결과`로 명확히 비활성화한다. 늦게 도착한 요청이 새 날짜 결과를 덮어쓰지 않도록 AbortController 또는 request token을 사용한다.
- AI는 사용자의 명시적 시작 버튼으로만 호출한다. 날짜 선택·페이지 이동만으로 유료 호출하지 않는다.
- AI 완료는 `검토 의견이 준비되었습니다`로 알리고 결과 제목에 focus; 전체 대답으로 강제 스크롤하지 않는다.
- 인용은 실제 조회한 id·uploadId·sourceRowNumber 기반. 원본 데이터의 메모 문자열은 HTML로 삽입하지 않는다.
- summary 로딩은 최소 높이를 유지한 skeleton 또는 지역 로딩 표시; 빈 결과와 구분. 재시도는 선택 날짜를 유지한다.
- 원본 표는 데스크톱에서 정렬된 열, 모바일에서는 카드 또는 핵심 열+지역 가로 스크롤. 페이지 전체 가로 넘침 금지.
- tab/shift-tab으로 날짜, 조회, AI 시작, 근거, 원본 페이지 이동 가능. native button/a 사용. alert 오류·status 로딩·aria-selected 탭 의미 적용.
- `prefers-reduced-motion`에서 비필수 전환·반복 animation 제거. focus와 상태는 색상 외 굵기/아이콘/문구로 전달한다.

## 구현 후 검증 계획

실제 브라우저에서 데스크톱 1440×1000과 모바일 390×844를 확인한다. 최소 캡처는 합계 일치 요약/원본, 자료 없음, AI 완료·근거, 모바일이다. AI 실제 모델 실행과 UI 테스트용 고정 응답은 결과에서 명확히 구분한다. 키가 없으면 AI 완료 스크린샷은 모델 검증을 뜻하지 않는다.

필수 확인: ① 날짜 선택→요약→AI→근거 이동 ② 날짜 변경 중 요청 경합 ③ 빈 결과/로딩/오류/재시도 ④ 긴 파일명·큰 금액·긴 메모 ⑤ 키보드와 focus ⑥ 390px overflow ⑦ 각 상태 대비와 색상 외 표현. 실제 발견·수정 내역과 스크린샷 경로는 구현 후 기록한다.

- 데스크톱 1440px, 모바일 390px에서 렌더링·페이지 가로 넘침 없음 확인.

## 2026-11-01 재개 마감·회귀 검증

최신 게시 환경의 파일을 기준으로 확인했다. 이미 반영돼 있던 neutral 상태 초기화, 모바일 상세의 거래 유형·기재내용, 서버 처리 취소를 보장하지 않는 진행 문구를 그대로 유지하고 회귀 검증했다.

이번 마감에서 다음을 보완했다.

- AI 검토가 페이지 최초 조회보다 새 자료를 읽었을 때, 반환된 Java `summary`를 상단 금액·건수·검토 상태에 반영한 뒤 원본과 관련 업로드를 다시 읽고 결과를 표시한다. 예전 금액과 새 AI 근거를 함께 보여주지 않는다.
- 검토 중 자료 변경으로 `AI_DATA_CHANGED` 409가 오면 AI 재시도를 잠근다. `하루 다시 조회`로 최신 내역을 확인해야 다시 검토할 수 있으며, 이 조회 버튼이 새 모델 요청을 만들지 않음을 확인했다.
- 원본 필터·페이지가 바뀌거나 요청이 중단되면 늦게 도착한 이전 응답을 채택하지 않도록 현재 요청 조건도 확인한다.
- AI 근거는 `검토 시점에 조회한 근거`로 표시한다. 아래 원본 목록은 다시 조회한 내역이라 이후 변경 사항이 반영될 수 있음을 설명한다. 전체 요청을 하나의 DB 스냅샷으로 보장한다고 주장하지 않는다.
- 첫 사용 안내에 UTF-8 CSV, 업무 예제 양식, 은행 기본·우리은행 양식과 다른 양식의 열 맞춤 필요를 명시했다. 예제의 −10,000원 차이는 같은 날짜의 다른 자료가 합산되면 달라질 수 있다는 기존 설명을 유지했다.

실제 시스템 Chromium + Python Playwright에서 **12개 흐름 통과**, pageerror 0. 기존 8개 흐름을 유지하면서 새 요약 동기화, 취소 문구, 409의 하루 재조회, 검토 상태 색상 초기화를 추가했다. 모바일 근거 상세의 거래 유형도 확인했다. 화면은 1440px 데스크톱과 390px 모바일에서 직접 렌더링·시각 확인했으며 페이지 가로 넘침이 없었다.

```bash
python scripts/verify-ai-review-browser.py --prefix nov01-
```

유료 모델 POST는 모든 브라우저 컨텍스트에서 가로채며 실제 모델 호출은 0회다. 성공·오류·자료 변경은 명시적인 UI fixture로 검증했다. DB 원본을 추가하거나 변경하지 않았다.
