# 입출금 대사 AI 검토: 시장·레퍼런스 조사

> 문서 범위: 초기 AI 검토 서비스 조사 기록이다. 본문의 당시 구현·가입/권한 상태와 적용 제안은 현재 완료 상태를 뜻하지 않는다. 미수금 서비스로의 재사용 판단은 [시장 가설](receivables-market-plan.md)에 있으며, 실제 고객 검증은 미완료다.

확인일: **2026-11-01 (Asia/Seoul)**. 2026-10-31의 해외 오픈소스 중심 조사에 국내·상용·Excel 비교를 보강했다. 목표는 현재 도메인의 하루 예정·실제 입출금 차이 검토이며, ERP·세무·금융 플랫폼으로 범위를 바꾸지 않는다.

## 조사 상태와 증거 범위

이전에는 일반 웹 도메인이 프록시 403으로 차단됐다. 이번에는 허용 설정이 적용된 상태에서 **이카운트, 캐시노트, Microsoft Excel 공식 도움말, Xero, QuickBooks, Wave 공식 기능·가격 페이지의 HTTP 200 본문을 직접 읽었다.** 이카운트 은행계좌 기능, 캐시노트 첫 화면, Xero 대사 소개는 실제 Chromium으로 렌더링하고 캡처를 열어 시각 확인했다. 기존 Actual·Frappe Books와 합쳐 **핵심 비교군 8개**를 선정했다.

공개 소개·가격·문서와 가입 후 실제 사용은 구분한다. 가입, 결제, 은행 연결, 외부 커뮤니티 게시, 고객 인터뷰는 하지 않았다. 캐시노트의 외부 이미지 일부는 브라우저에서 불러오지 못해 텍스트·레이아웃 중심으로 확인했다. 아래 첫 사용 흐름은 공개 진입 화면·공식 설명에 근거하며 가입 후 모든 단계를 직접 완료했다는 뜻이 아니다.

**현재 확인한 것은 대안의 기능·진입 방식·일부 사용자 문제다. 이 프로젝트의 실제 수요, 지불 의사, 유입 성과, 반복 사용은 아직 검증하지 못했다.** 시장 규모·사용자 수·매출·전환율을 추정해 성과처럼 쓰지 않는다. 공식 사이트의 홍보 문구나 선정 후기도 독립적인 성과 증거로 삼지 않는다.

## 공개 후기·질문에서 확인한 문제와 한계

2026-11-01 아래 공개 이슈 본문·답변을 다시 읽었다. 개별 보고와 유지보수자의 답변을 구분하며, 문제의 시장 발생률이나 한국 경리 담당자의 빈도로 일반화하지 않는다.

1. **뒤늦게 확정되는 거래와 CSV 재가져오기.** [hledger #1943](https://github.com/hledgerorg/hledger/issues/1943)에는 2022년 최초 보고뿐 아니라 2025년 다른 사용자의 같은 문제·전처리 우회 사례가 있다. 유지보수자는 날짜 기반 중복 제거의 한계를 인정하며 동일하게 보이는 별개 거래가 실제 존재한다고 설명했다. **관찰:** 이 이슈 안에서는 문제가 시차를 두고 반복 보고됐다. **적용:** 파일 등록시각과 거래일을 구분하고 원본 ID·행·업로드를 추적한다. 조회 0건만으로 미업로드를 단정하지 않는다.
2. **일치 표시와 비교 근거의 신뢰.** [ERPNext #62902](https://github.com/frappe/erpnext/issues/62902)의 사용자는 표시 금액이 같아도 불일치 아이콘이 나오는 경우와 날짜가 먼 후보의 순위를 보고했다. 부동소수점·자료형 관련 원인과 수정안은 보고자의 추정이며 우리 조사에서 재현하지 않았다. **적용:** Java 정수 계산을 유지하고 합계·자료 존재·개별 매칭을 다른 상태로 표현한다.
3. **자동 매칭은 의도한 동작이어도 사용자가 기대한 원본을 숨길 수 있다.** [Actual #7855](https://github.com/actualbudget/actual/issues/7855)는 동기화가 다른 split 거래에 연결됐다고 보고했다. 자동 triage는 AI 작성이라고 명시돼 있어 검증된 원인으로 쓰지 않았다. **중요한 답변:** 유지보수자는 split 매칭이 의도된 동작이라고 설명하고 `not planned`로 종료했다. 따라서 이를 현행 제품의 확정 버그라고 부르면 안 된다. **적용:** 이번 제품은 자동 매칭·수정 없이 사람이 원본을 확인하도록 한다.
4. **국내 첫 사용의 편의성.** 캐시노트 공식 선정 후기에는 '컴퓨터를 잘 다루지 못하지만 간단한 연동으로 매출·비용을 본다'와 '개별로 확인하지 않고 한 번에 알려준다'는 서술이 있다. **한계:** 서비스가 고른 긍정 후기이고 독립 표본·불편 비중·재현 검증이 아니다. **적용 가설:** 파일 재가공·개별 화면 이동이 많으면 도입 장벽이 된다. 실제 국내 실무자에게 별도로 확인해야 한다.
5. **홍보 후기는 성과 검증과 다르다.** Wave 가격 페이지의 한 절약시간 후기는 무료 연간 구독과 $150 기프트카드를 제공받았다고 명시한다. 선정·보상 후기를 일반적인 시간 절약률이나 우리 제품의 목표 달성 근거로 쓰지 않는다.

Excel의 공식 지침은 자료를 단일 헤더·열 구조로 정리하고 새 자료 추가 후 피벗을 갱신해야 한다고 설명한다. 이는 전처리·갱신 단계가 존재한다는 **작업 근거**이며 고객 불만의 발생률을 보여주는 후기는 아니다.

QuickBooks 공개 질문 주소 하나는 요청한 주제와 무관한 보관 문서로 이동한 뒤 502가 났고, 지원 검색도 타임아웃이었다. 해당 내용을 대사 문제 근거로 인용하지 않았다. 국내 실무 커뮤니티의 독립 후기·실제 회사 파일·반복 사용과 구매 의사는 아직 확인하지 못했다.

## 이 프로젝트의 고객·사용 상황·차별점 가설

**우선 고객 가설:** 업무에서 충전·후불 정산·환불의 예정 내역을 관리하고 은행 CSV와 비교하는 소기업의 경리·정산 담당자. '모든 소상공인'으로 넓히지 않는다. 캐시노트의 매장 매출 고객, Actual의 개인 예산 고객과도 동일하지 않다.

**대표 상황:** 오늘 예정 입금과 통장 합계가 다른 날짜를 발견한다. 업무표와 은행 자료를 등록하고 입금·출금을 따로 비교한다. 어느 원본과 파일을 확인할지 찾아보고, AI의 추정·확인 질문을 참고해 사람이 판단한다. 현재 집계는 날짜별 합계이므로 개별 누락 거래를 확정해서 찾아준다고 약속하지 않는다.

**선택 이유로 검증할 가설:** 전체 회계 장부를 이전하거나 은행 계좌를 새 서비스에 연결하기 전에, 이미 가진 두 자료로 하루 예정·실제 차이와 원본 근거를 한 흐름에서 확인한다. AI 설명은 보조다. Xero 등도 이미 AI와 이유 설명을 제공하므로 'AI를 쓴다'는 사실 자체는 차별화의 충분한 근거가 아니다.

**현재 가장 큰 반증 가능성:** 고객이 업무표·통장 파일을 우리 고정 CSV 열로 많이 고쳐야 한다면 엑셀보다 편하다는 전환 이유가 사라질 수 있다. 파일 준비·오류 수정·거래처 등록까지 포함한 전체 시간을 비교해야 한다. '은행 파일 자동 호환', 'AI가 누락을 확정'과 같은 현재 미구현 약속은 하지 않는다.

현재 코드의 범위는 UTF-8 업무 CSV, 은행 기본 양식과 우리은행 거래 표 CSV다. 지원 은행·형식, 거래처 선등록, 다른 양식은 열 맞춤이 필요하다는 안내를 첫 사용에서 보여준다. 가입/회사별 권한이 없는 현재 로컬 시제품을 공개 운영 서비스로 소개하지 않는다.

## 첫 방문에서 첫 대사까지

1. **대상·과업 이해:** '업무 예정 내역과 은행 거래를 날짜별로 비교하고 원본을 확인한다'를 먼저 설명한다. 읽기 전용 AI이며 합계 일치와 개별 매칭이 다름을 보여준다.
2. **준비 비용 확인:** 지원 형식·은행 범위와 개인정보/외부 AI 전송을 안내한다. 자기 파일을 바로 쓸 수 있는지, 변환이 필요한지 사용 전에 알게 한다.
3. **합성 예제로 가치 확인:** 거래처 등록 → 업무·은행 예제 CSV → 날짜 조회의 짧은 안내를 제공한다. 예제와 실제 자료가 함께 집계될 수 있으므로 예제 차이 금액을 모든 환경에서 고정된 결과로 약속하지 않는다. 이번에 자동으로 고객 자료에 예제를 추가하지 않았다.
4. **자기 자료로 첫 대사:** 검증 오류에서 문제 필드·행을 확인하고 수정한다. 업로드 성공 뒤 날짜를 고르면 자료 건수·입금/출금 차이·원본이 연결돼야 한다.
5. **필요 시 AI 요청:** 명시적인 요청 버튼으로만 호출하고 비용·실패·재시도를 관리한다. 사실·가능한 원인·추가 확인을 구분한다. 실제 모델 검증 전 성공한 서비스처럼 안내하지 않는다.
6. **사람의 확인:** 인용 원본·업로드를 열어 확인한다. AI는 거래나 검토 완료를 저장하지 않는다.

## 실제 사용자 파일럿에서 확인할 기준

아직 실무자 인터뷰·사용성 세션·유입 성과는 없다. 다음은 사전 정의할 평가 항목이며 현재 달성 성과가 아니다.

- **적합 고객:** 같은 업무를 정기적으로 하는지, 사용하는 예정표·은행 파일과 기존 절차가 무엇인지. 연락이나 파일 수집은 권한·동의 후 진행한다.
- **첫 가치 도달:** 두 자료를 등록하고 하루 요약과 최소 한 원본 근거를 확인하기까지의 비율·전체 시간. 단순 화면 방문이나 AI 답변 수신만을 완료로 세지 않는다.
- **전환 가치:** 기존 엑셀 절차와 같은 표본·과업으로 파일 준비/오류 수정/확인까지 비교한다. 원본을 더 빨리 찾는지와 추가로 생긴 작업을 함께 기록한다.
- **업무 정확성:** Java 금액과 화면/AI 사실 불일치, 자료 없음 오판, 합계를 개별 매칭으로 단정, 조회 안 된 근거, 미업로드 단정 발생 건수. 0건을 목표로 두되 측정 전 달성했다고 쓰지 않는다.
- **AI 효용·비용:** 실제 호출 승인 후 성공률·지연·검토당 요청 수/비용, 근거 클릭, 유용함/추가확인필요 응답. 조회 도구가 잘 호출돼도 해석이 유용한지 별도 평가한다.
- **반복 사용:** 다음 업무일/마감의 재방문과 자기 자료 재사용, 돌아오지 않은 이유. 초기 소수 표본을 시장 전체 전환율로 일반화하지 않는다.
- **개인정보:** 분석 이벤트에 원본 텍스트·파일명·비밀값을 넣지 않고, 금액도 기본 이벤트 속성에서 제외한다. 인증·회사/계좌별 권한·보존/삭제·외부 AI 전송 정책이 파일럿의 전제다.
