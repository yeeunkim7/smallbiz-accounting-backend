# 소사업자 청구·입금·미수 관리 시장 가설

> 문서 범위: 고객·가격·화면의 가설 문서다. 연체 건수·샘플 후보 체험 등 제안이 모두 구현됐다는 뜻은 아니다. 현재 샘플은 로컬 읽기 전용이며 구현 범위는 [개발 계획](RECEIVABLES_FREE_MVP_PLAN.md)을 따른다.

조사 기준일: **2026-11-01 (Asia/Seoul)**  
이 문서는 방향 전환용 경량 조사다. 선행 조사 [ai-review-research.md](ai-review-research.md)의 비교군 8개와 검증 범위를 재사용한다. 해당 자료의 가격·기능 확인일(2026-11-01) 및 Actual/Frappe 자료 확인일(2026-10-31)은 원문에 적힌 날짜를 유지한다. 과거 조사는 예정/실제 입출금 대사가 목적이었으므로 이 문서의 청구→입금→매칭→미수관리 수요를 입증하지 않는다.

## 제품 가설

소사업자 중 외상·후불 청구가 반복되는 1인 사업자와 소규모 팀이 고객별 청구액, 실제 입금, 미수 잔액과 연체를 한눈에 확인하도록 돕는다. 기본 흐름은 **청구 등록 → 입금 등록/자료 입력 → 시스템이 매칭 후보 표시 → 사람이 확정 → 미수·연체 확인**이다. 후보는 제안일 뿐 자동 확정이나 독촉 발송을 의미하지 않는다. 모바일 Expo 앱을 우선하며 현장·이동 중 직접 청구와 입금을 입력할 수 있게 한다. FREE는 AI 호출 0회다.

## 첫 화면, 진입 장벽, 차별 가설

첫 화면은 모바일에서 오늘 청구 합계, 입금 합계, 미수 잔액과 연체 건수를 먼저 보여주고, `청구 추가`와 `입금 추가`를 주요 행동으로 둔다. 각 미수 행에서 고객·청구일·기한·잔액을 보고 입금 후보를 검토한 뒤 사람이 확정한다. 데이터가 없을 때는 상태 숫자를 0으로 위장하지 않고 첫 청구 등록과 합성 샘플 둘 중 하나로 시작하게 한다.

가장 큰 첫 사용 장벽은 고객·청구 목록을 준비하거나 기존 파일을 옮기는 일이다. 그래서 직접 입력은 MVP의 필수 경로이고, 예제 고객/청구/입금 데이터는 별도 샘플 작업공간에서 가치와 매칭 후보를 즉시 체험하도록 제공할 필요가 있다. 샘플이 실제 장부와 섞이거나 실자료처럼 보이면 안 된다. 파일 업로드는 실제 고객 파일 표본과 변환 부담을 확인한 뒤 순위를 정한다. Expo 모바일에서 고객 선택, 금액/기한 입력, 입금 기록, 후보 확인을 짧게 끝내는 것이 우선이다.

차별 가설은 회계 ERP를 교체하지 않고 작은 팀이 모바일에서 청구와 입금을 기록하고, 미수와 연체를 즉시 파악하며, 애매한 입금 연결은 사람이 통제한다는 점이다. 이를 아직 검증된 경쟁우위로 말할 수 없다. 선행 조사에서 확인한 대안은 자동 대사와 회계 기능을 제공하지만 이 새 과업에서의 사용성 비교는 하지 않았다.

## 가격 가설과 범위

| 가설 | 검증할 내용 |
| --- | --- |
| FREE, AI 0회 | 청구/입금 직접 등록, 매칭 후보, 사람 확정, 기본 미수/연체 조회를 핵심 체험으로 둔다. 무료 사용자가 반복 업무에 충분한지, 유료 전환 이유가 생기는지 관찰 |
| 월 9,900원 | 소규모 반복 사용자가 고객/청구 내역 보관과 일상 미수 관리에 지불할지 인터뷰·파일럿에서 검증. 확정 가격 아님 |
| 월 약 30,000원 | 복수 사용자·확장 리포트 등 추가 가치가 필요한 사업자의 지불의사 가설. 기능과 가격 모두 미확정 |

세 가격은 제품 실험용 가설이며 기존 경쟁사 가격에서 도출한 시장 사실이 아니다. AI는 무료 플랜에서 호출하지 않는다. 유료 AI 보조를 시험하더라도 사람 확정 흐름과 비용 한도를 먼저 정하고, 요청 수·오류·실제 효용을 측정한다.

초기 범위는 고객, 청구, 입금, 수동 매칭 확정, 미수/연체 목록, 샘플 워크스페이스와 모바일 직접 입력이다. 후순위는 은행 자동연결, 자동 확정/독촉 발송, 세금계산서 발행, ERP·회계 전체 기능, 다통화, 파일 열 자동 매핑이다. 외부 메시지 전송·결제·은행 연결은 이번 조사나 구현에서 실행하지 않았다.

## 파일럿에서 볼 지표

아직 인터뷰·실사용·성과 측정은 없다. 제한된 파일럿을 준비할 때 다음을 측정한다: 적합 고객(정기적으로 후불 청구·입금을 관리하는지), 첫 청구부터 입금 후보 확인 및 확정까지의 시간, 매칭 후보 수락/수정/미확정 비율, 미수 잔액 확인까지 걸린 시간, 다음 청구 주기의 재사용, 기존 엑셀 대비 준비·정리 작업시간, 직접 입력과 샘플의 첫 가치 도달률, 가격별 지불 의향. 유입은 출처별 적격 방문→첫 청구 등록→첫 입금 매칭→반복 사용으로 기록하고, 단순 노출/가입을 성과로 부르지 않는다. 소수 파일럿 결과를 전체 시장으로 일반화하지 않는다.

## 조사 접근 한계

2026-11-01 실행 시 `/etc/codex/network-policy.json`상 `www.serp.co.kr`, `cashnote.kr`, `www.ecount.com`은 허용 목록에 있었다. 기본 sandbox 요청은 `proxy:8080` 연결 실패로 끝났고, 허용된 `www.serp.co.kr`에 대한 escalated HTTPS 진단 요청은 HTTP 403을 받았다. 둘은 서로 다른 실패다. 정책에 없는 kyungrinara.com이나 볼타·대사노트 도메인을 임의로 열거나 proxy/네트워크 설정을 변경하지 않았다. 따라서 본 문서는 기존 공식자료를 재사용하고 미확인을 표시한 경량 가설 문서이지 신규 제품 검증 보고서가 아니다.
