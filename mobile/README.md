# 차곡 모바일 코어

소사업자를 위한 미수금 장부. 공식 Expo TypeScript 템플릿 기반의 iOS·Android 공통 앱이며 같은 React Native 화면을 웹에서도 검증할 수 있다.

현재 기능은 로그인·가입·세션, 서버 전체 잔액 홈, 거래처·청구·입금 직접 등록, 페이지 목록, 청구 현재 잔액 상세, 서버 월 사용량·로그아웃, 입금 연결 검토·확정·취소다. CSV 가져오기 UI는 후속 범위다. [입금 연결 설계와 계약](../docs/RECEIVABLES_MOBILE_MATCHING.md)을 따른다.

## 로컬 실행

Node 24 / npm 11로 확인했다. Expo SDK 58, React Native 0.88.1, React 19.3.0, TypeScript 6.0.3을 공식 템플릿과 Expo의 bundledNativeModules에 맞췄다. 정확한 설치 버전은 package-lock.json을 따른다.

```sh
cd mobile
npm ci
cp .env.example .env
npm run web
```

`.env`의 `EXPO_PUBLIC_API_URL`은 API **origin**만 받는다. 경로·쿼리·해시·사용자 정보가 있는 URL은 거부한다. 토큰, 비밀번호, 서버 비밀 설정을 넣지 않는다. 기본 예시는 `http://127.0.0.1:8091`이며 해당 백엔드가 실제 실행 중이어야 한다. 공개 환경은 HTTPS를 사용한다. 로컬 브라우저 origin은 백엔드 CORS 설정에서 명시적으로 허용해야 한다. [백엔드와 Windows PowerShell 실행 절차](../docs/RECEIVABLES_MOBILE_VALIDATION.md)를 참고한다.

Android/iPhone은 `127.0.0.1`이 PC를 가리키지 않는다. API 주소를 개발 PC의 접근 가능한 LAN 주소로 바꾸고 `npm run start` 후 Expo가 표시하는 로컬 개발 흐름을 따른다. Expo Go/기기 설치·SecureStore·키보드·안전 영역은 실제 기기에서 아직 확인하지 않았다. iOS Simulator 실행은 macOS 도구가 필요하다. Windows 개발과 Android/iPhone 실기기 확인은 배포 게이트로 남는다.

네트워크가 제한된 환경에서는 이미 설치된 Expo 호환 정보로 `EXPO_OFFLINE=1 npx expo install --check`를 실행할 수 있다. 실제 공개 배포·tunnel·EAS·스토어·서명·인앱 결제 설정은 하지 않았다. 앱의 bundle/package identifier도 배포용으로 설정하지 않았다.

## 첫 이용

- `샘플 체험`은 가입 없이 읽기 전용 합성 자료를 보여준다. 고정 기준일 2026.11.01과 샘플 표시가 유지되며 실제 API·기기 토큰 저장·사용량을 사용하지 않는다. 종료하면 로그인 화면으로 돌아간다.
- 실제 계정은 아이디(이메일 소유권 인증 아님), 12자 이상 비밀번호, 사업장 이름으로 가입한다. 복구·이메일 인증·사업장 생성/초대 기능은 없다.
- 거래처 등록 후 청구를 추가한다. 입금은 독립 기록이며 청구 상환으로 자동 처리하지 않는다. 여러 소속 사업장이 있는 계정은 서버 소속 목록에서 선택한다.
- 홈 합계와 개별 청구/입금 잔액은 서버에서 조회한다. 각 페이지에서 보이는 항목의 잔액만 읽으며 목록 일부를 전체 금액으로 합산하지 않는다.

## 보안·오류 동작

Native bearer는 Expo SecureStore(기기 잠금 해제 후 접근, 기기 한정)에 보관한다. 저장 실패는 로그인 완료로 처리하지 않으며 발급 세션 폐기를 시도하고 기기 상태를 지운다. Web은 메모리에만 보관하여 페이지 새로고침 시 로그아웃된다. localStorage/sessionStorage/cookie에 bearer를 보관하지 않는다.

조회·POST에는 12초 타임아웃이 있으며 자동 재시도하지 않는다. 현재 세션의 401은 화면을 잠그고 토큰을 지운다. 세션 세대와 화면 조회 취소 표시로 이전 계정·사업장의 늦은 응답을 표시하지 않는다. 로그아웃은 즉시 로컬 UI/토큰을 지우고 서버 폐기를 확인한다. 서버 폐기를 확인하지 못하면 해당 사실을 안내한다.

금융 등록은 자원별 UUID `Idempotency-Key`를 사용한다. 동일한 정규화 payload의 불확실한 실패 후에는 같은 키를 유지한다. 내용이 달라지거나 성공 후 새로 등록할 때 새 키를 만든다. 전송 중 입력과 탐색(Android 뒤로 포함)을 잠가 중복 제출·초안 교체를 막는다. 성공한 POST 이후의 장부 조회 실패는 별도의 조회 오류이며 등록 성공 안내를 유지한다. 가입/로그인은 키가 없는 API이므로 자동 재시도하지 않으며 가입 결과가 불확실하면 먼저 로그인을 안내한다.

초안은 해당 사업장의 메모리 안에 유지하며 로그아웃·사업장 변경·앱 종료 때 버린다. 금액은 문자열/BigInt로만 처리한다. 날짜는 실제 달력 날짜를 검증하고 서울의 오늘을 사용하며 입력 날짜를 UTC로 변환하지 않는다. FREE 기본 업무에는 AI 경로나 키가 없다.

## 검사

```sh
npm test
npm run typecheck
npx expo export --platform web
```

`npm test`는 Node 내장 테스트 하네스로 기존 핵심 8개와 입금 연결 상태 5개 검사를 실행한다(중복 요청 키, 재시도 금지, 세션 경합/401/저장 순서, URL, 브라우저 fetch 바인딩, 정밀 금액·날짜). 입금 연결 검사는 다대다 초안·쌍 유일성·정규화 명령 키·명시적 최종 검토 조건·날짜 범위·서버 한도 오류를 확인한다. 실제 브라우저·기기 검증 상태와 남은 작업은 [모바일 코어 결정](../docs/RECEIVABLES_MOBILE_CORE.md), [실제 검증 기록](../docs/RECEIVABLES_MOBILE_VALIDATION.md)을 따른다.

## 입금 연결

입금 연결 탭에서 범위를 입력해 후보를 생성하거나 기존 실행을 무료 조회한다. 정상 저장은 자료·후보 0건도 1회이며 실패는 차감되지 않는다. 한도와 초기화는 서버 응답을 표시한다. 수동 연결·취소와 모든 조회는 한도 소진 후에도 사용할 수 있다.

후보는 저장 당시 이름·날짜·정확한 금액 근거이며 현재 잔액과 다를 수 있다. 후보 또는 직접 판단한 입금·청구를 여러 행으로 담고 금액을 입력한 뒤 현재 잔액을 서버에서 조회한다. 별도 ‘연결 확정’을 눌러야 저장한다. 합계·연결 후 잔액을 클라이언트에서 계산하지 않는다. 원본 출처는 사용자가 열 때 tenant API에서 조회하며 파일을 추정하지 않는다.

이력에서 사유를 입력하고 별도 확인 후 전체 연결을 취소할 수 있다. 확정/취소 응답은 명령 당시의 불변 결과이므로 현재 상태는 GET으로 다시 읽는다. 조회 실패를 금융 명령 실패로 표시하지 않는다. 초안과 정규화 요청 키는 사업장 메모리에 유지하고 불확실한 실패는 사용자가 같은 내용으로 재시도한다. 자동 재시도·자동 확정·실제 돈 이동·AI 호출은 없다.

샘플에서는 이 기능의 읽기 전용 안내만 제공하며 API나 사용량을 호출하지 않는다. API와 세션 어댑터를 유지하며 Apps in Toss SDK를 설치하지 않았다. 실제 Android/iPhone 기기 검증은 아직 수행하지 않았다.


## 입금 등록 응답 유실 후 복구

입금 등록은 POST 전에 요청 키와 정확한 입력을 보관한다. 실패 후 앱·브라우저를 다시 열고 같은 계정·사업장에 로그인하면 ‘확인이 필요한 입금 등록’이 표시된다. ‘등록 결과 다시 확인’을 누를 때만 기존 키·내용으로 재전송하며, 응답 유실 전에 이미 저장됐으면 같은 입금을 반환한다. 새 요청을 만들거나 자동 재시도하지 않는다. 저장소를 읽거나 쓸 수 없으면 새 입금을 전송하지 않는다.

Native는 SecureStore(보관 값 UTF-8 1800바이트 상한), Web은 IndexedDB를 사용한다. Web의 금융 입력 원문은 앱 자체 암호화 없이 사이트 데이터에 남는다. 토큰은 포함하지 않으며 서버 주소·계정·사업체로 구분한다. 성공 확인 후 보관을 삭제하고, 미확인 상태는 로그아웃해도 유지한다. 사이트 데이터 삭제나 앱 제거 뒤에는 복구를 보장하지 않는다. 청구·배분·취소 복구는 아직 메모리 범위다.

단위 검증은 `npm test`, 타입 검사는 `npm run typecheck`를 사용한다. 실제 Java·브라우저 검증은 저장소 루트의 `scripts/verify-payment-recovery-browser.py`이며 localhost 8091/8081과 전용 reconciliation_test/chagok_test 설정만 사용한다. 만든 계정만 정리하며 캡처는 저장소 밖에 보관한다. iOS/Android 실기기 검증과 구분한다.
